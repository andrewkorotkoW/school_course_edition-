# EduQuest

Образовательная платформа для школьников. Полная концепция возрастных зон — в [docs/CONCEPT.md](docs/CONCEPT.md) (описывает более ранний взгляд на продукт, часть решений там уже пересмотрена — см. ниже).

## Текущее направление (пересмотрено 20.10.2026)

Проект разворачивается от детского игрового MVP (квесты + магазин + 3D-городок) к платформе
с админкой:

- **Админка** собирает программу обучения из областей/предметов, которые выбирает администратор.
- Для основных предметов есть **готовые шаблоны** — не начинать с нуля каждый раз.
- Охват — школьная программа **1–5 класс**.
- Ученик проходит собранную программу — существующий механизм "квест → задания → проверка"
  переиспользуется как единица содержания программы.

Игровой слой (баллы, магазин построек, 3D-сцена) из прошлой версии MVP удалён осознанно
(20.10.2026) — см. «История решений» ниже. Модель данных (Subject/Quest/Task/Progress) оставлена
и переиспользуется.

## Стек

Backend — Python/FastAPI + SQLAlchemy + PostgreSQL. Frontend — Next.js (React, TypeScript).
Dev-окружение — Docker Compose. Стек выбран как продолжение уже обкатанного в этом репозитории,
без смены ради новой фичи.

## Структура репозитория

```
backend/            FastAPI-приложение
  app/
    core/            конфигурация
    db/               подключение к БД, сид тестовых данных
    models/          SQLAlchemy-модели (Parent, Student, Subject, Quest, Task, Progress)
    schemas/         Pydantic-схемы
    api/routes/      эндпоинты
frontend/            Next.js-приложение
  app/                страницы (/, /quest/[id])
docs/
  CONCEPT.md           концепция возрастных зон и игровых механик (частично устарела, см. выше)
docker-compose.yml
.env.example
```

## Быстрый старт

```bash
cp .env.example .env
docker compose up --build
```

- Backend: http://localhost:8000 (`/health`, `/subjects`, `/subjects/{slug}/quests`, `/quests/{id}/tasks`)
- Frontend: http://localhost:3000

Засеять контент — предметы, демо-ученика, по квесту на каждый класс (1–4 пока, до расширения на
1–5) с заданиями по математике и русскому:

```bash
docker compose exec backend python -m app.db.seed
```

> На хосте установлен Node v12 — для фронтенда он слишком старый (Next.js требует 18+). Поэтому
> frontend собирается и запускается только внутри Docker (образ `node:20-alpine`) — локально
> `npm install`/`npm run dev` без контейнера работать не будет, пока вы не обновите Node на машине.

## Что ещё не реализовано

- Админки нет вообще — это и есть следующая задача.
- Нет миграций (Alembic) — таблицы создаются напрямую при старте backend.
- Нет авторизации/реальных ученических аккаунтов — везде используется захардкоженный
  `student_id=1` (сид создаёт для него демо-ученика).
- Контента пока по одному квесту (3 задания) на класс и предмет, только 1–4 класс и два предмета —
  достаточно, чтобы проверить механику заданий, мало для реального использования.
- Нет персистентности прохождения заданий внутри квеста — если обновить страницу на середине
  квеста, прогресс по заданиям сбрасывается.
- Нет родительского/учительского интерфейса.

## История решений

**Версия 1 (питомец).** Единственный питомец, растущий через 5 стадий с Phaser-анимацией
(процедурные фигуры). Отказались — геометрические фигуры не дают приемлемого визуального
качества, а Phaser-анимация добавляла хрупкости (игра сама ставится на паузу при потере вкладкой
фокуса).

**Версия 2 (городок с магазином).** Баллы за квесты → покупка построек (сначала эмодзи, потом
настоящие низкополигональные 3D-модели из набора Kenney, CC0) → городок на 3D-сцене
(Three.js/react-three-fiber). Решало проблему визуала версии 1 и подтверждалось живым разбором
рынка (docs/CONCEPT.md писался позже с опорой на этот анализ) — у немецкого Anton и ClassDojo
Dojo Islands похожая механика работает на десятках миллионов пользователей.

**Версия 3 (текущая, с 20.10.2026).** Сменился фокус: вместо детского игрового продукта —
платформа с админкой, которая собирает программу обучения из шаблонов по предметам, 1–5 класс.
Игровой слой версии 2 удалён целиком (код сохранён в истории git, в коммитах до 20.10.2026, если
понадобится вернуться). Модель контента (Quest/Task) оставлена — то, что раньше было "квестом с
наградой", теперь просто единица программы.
