# EduQuest

Образовательная платформа для школьников 1–11 класс, разделённая по игровым механикам под возраст. Полная концепция — в [docs/CONCEPT.md](docs/CONCEPT.md).

## Зафиксированные решения по MVP

- **Возраст**: 1–4 класс.
- **Механика**: выполненные квесты приносят баллы, баллы тратятся в магазине на постройки для своего городка. Без рейтингов, таймеров и публичного проигрыша — только накопление и личный выбор, что строить.
- **Визуал построек — эмодзи**, не хендмейд-иллюстрации: у проекта нет художника, а эмодзи — уже готовая профессиональная графика. Решение осознанно временное (см. "Что ещё не реализовано").
- **Предметы**: математика + русский язык.
- **Стек**: backend — Python/FastAPI + SQLAlchemy + PostgreSQL; frontend — Next.js (React); dev-окружение — Docker Compose.

## Структура репозитория

```
backend/            FastAPI-приложение
  app/
    core/            конфигурация, каталог построек (app/core/catalog.py)
    db/               подключение к БД, сид тестовых данных
    models/          SQLAlchemy-модели (Student, Subject, Quest, Task, Progress, Wallet, OwnedBuilding)
    schemas/         Pydantic-схемы
    services/        бизнес-логика, общая для нескольких роутов (app/services/town.py)
    api/routes/      эндпоинты
frontend/            Next.js-приложение
  app/                страницы (/, /quest/[id], /town)
docs/
  CONCEPT.md           полная концепция (возрастные зоны, игровые механики, открытые вопросы)
docker-compose.yml
.env.example
```

## Быстрый старт

```bash
cp .env.example .env
docker compose up --build
```

- Backend: http://localhost:8000 (`/health`, `/subjects`, `/buildings/catalog`, `/students/{id}/town`)
- Frontend: http://localhost:3000

Засеять контент — предметы, демо-ученика, по квесту на каждый класс (1–4) с заданиями по математике и русскому:

```bash
docker compose exec backend python -m app.db.seed
```

После этого на `http://localhost:3000` видно 8 квестов (4 класса × 2 предмета). Каждый квест проходится с реальными заданиями, начисляет баллы в кошелёк — потратить их можно в магазине на `/town` на одну из 8 построек (от домика за 10 до башни за 70 баллов).

> На хосте установлен Node v12 — для фронтенда он слишком старый (Next.js требует 18+). Поэтому frontend собирается и запускается только внутри Docker (образ `node:20-alpine`) — локально `npm install`/`npm run dev` без контейнера работать не будет, пока вы не обновите Node на машине.

## Что ещё не реализовано (сознательно, для MVP-среза)

- Нет миграций (Alembic) — таблицы создаются напрямую при старте backend.
- Нет авторизации/реальных ученических аккаунтов — везде используется захардкоженный `student_id=1` (сид создаёт для него демо-ученика).
- Контента пока по одному квесту (3 задания) на класс и предмет — достаточно, чтобы проверить механику, но мало для реального использования.
- Нет персистентности прохождения заданий внутри квеста — если обновить страницу на середине квеста, прогресс по заданиям (не по заработанным баллам) сбрасывается.
- Визуал построек — эмодзи, не кастомная иллюстрация. Для проверки механики достаточно; если механика "зайдёт" и продукт нужно будет показывать всерьёз (родителям, инвестору) — это первое, что стоит заменить на свой визуальный язык.
- Нет родительского/учительского интерфейса — см. открытые вопросы в [docs/CONCEPT.md](docs/CONCEPT.md).

## История решений

Изначально вместо городка/магазина был единственный питомец, растущий через 5 стадий с Phaser-анимацией (процедурные фигуры: круги, треугольники). От этой версии отказались — геометрические фигуры не дают приемлемого визуального качества независимо от того, сколько их полировать, а анимация добавляла сложности (Phaser по умолчанию ставит игру на паузу при потере вкладкой фокуса, что ломает тайминги таймеров/твинов). Заменено на коллекционную механику с магазином построек — тот же принцип "без рейтингов и проигрышей", но без необходимости рисовать персонажа.
