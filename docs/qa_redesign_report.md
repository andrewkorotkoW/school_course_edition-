# QA-отчёт: редизайн (пазлы, доступность, адаптивность)

Дата: 2026-10-21

## Как проверялось

Эта сессия работает в изолированном git-worktree, где `docker compose up/run`,
`docker exec` и любые сетевые запросы (`curl`, `npm install` из контейнера)
стабильно возвращают отказ на уровне sandbox-разрешений — без диалога
подтверждения, который можно было бы одобрить. Подтверждено повторными
попытками: `docker exec frontend node -v`, `docker compose run --rm frontend
npm install`, `curl localhost:3000` — все заблокированы. Файловый доступ тоже
ограничен текущим worktree (нельзя даже проверить, есть ли на хосте другая
версия Node). Поэтому:

- **Живой прогон в браузере (360/768/1024/1280px, console-ошибки, resume по
  F5, анимации) не выполнялся** — нужен реальный браузер, которого у меня в
  этой сессии нет. Сделайте этот проход сами на `http://localhost:3000`
  (контейнеры `school_course_edition--frontend-1`/`backend-1`/`db-1` уже
  подняты и работают).
- Там, где дефект можно доказать без браузера — точным расчётом или чтением
  кода — я это сделал. Ниже только проверяемые находки, а не предположения.

## Найденные дефекты

### 1. Текст на основной кнопке не проходит контраст WCAG AA
Белый текст (`#ffffff`) на фоне `--color-primary` (`#ff7a3d`) даёт контраст
**2.59:1** — ниже требуемых 4.5:1 для обычного текста (и ниже даже
послабленных 3:1 для крупного/жирного текста, под которые эта кнопка всё
равно не подпадает: 16–17.6px при weight 600).

- Где: `frontend/app/globals.css:194-201` (`.btn-primary`, `.btn-primary:hover`)
- Затрагивает: кнопки «Готово» (оба пазла), «Проверить», «Дальше →»,
  «← К заданиям» на экране завершения квеста.
- Как проверить: взять фон `#ff7a3d` и текст `#ffffff`, посчитать WCAG
  contrast ratio (например, в DevTools → Accessibility → Contrast, или любым
  онлайн-калькулятором) — должно показать ~2.6:1 и предупреждение AA.

### 2. Текст «✓ Верно!» и плашки порядка в OrderTapPuzzle не проходят контраст
`--color-success` (`#2fa88a`) на `--color-success-bg` (`#e4f7f0`) даёт
**2.66:1** — ниже 4.5:1 для обычного текста этого размера.

- Где: `frontend/app/globals.css:403-412` (`.quest-feedback-success-text`,
  18.4px/700) и `frontend/app/globals.css:633-641` (`.order-tap-pill`,
  17.6px/600)
- Затрагивает: текст «✓ Верно!» после правильного ответа и зелёные плашки
  с уже расставленным порядком в `OrderTapPuzzle`.

### 3. Текст объяснения ошибки тоже ниже порога AA
`--color-error` (`#e2483d`) на `--color-error-bg` (`#fdeceb`) — **3.51:1**,
текст 16px normal-weight, нужно 4.5:1.

- Где: `frontend/app/globals.css:414-422` (`.quest-feedback-error-text`)
- Затрагивает: «Пока не то. {объяснение}» после неверного ответа.

### 4. Поле ввода в задачах типа `input` без доступного имени
`<input className="quest-input" .../>` не имеет ни `<label>`, ни
`aria-label`, ни `placeholder` — скринридер объявит просто «edit text»
без контекста, что туда вводить.

- Где: `frontend/app/quest/[id]/page.tsx:183-187`
- Нарушение: WCAG 1.3.1 / 4.1.2 (Name, Role, Value).

## Что проверено и дефектов не найдено

- **Тач-таргеты ≥44px**: `.btn` (44px), `.count-click-item`/`.order-tap-tile`
  (48px), `.quest-input` (44px), `.quest-card` (44px + padding) — у всех
  интерактивных элементов `min-height`/`min-width` в CSS не ниже 44px, значит
  вне зависимости от контента целевая область не просядет ниже порога.
- Остальные пары текст/фон из дизайн-системы (`--color-text` на `--color-bg`,
  `--color-text-muted` на `--color-bg`/`--color-surface`, заголовок на фоне,
  текст на `--color-accent`) дают 6:1–13:1 — заметный запас по AA.
- Логика резюме квеста (`frontend/app/quest/[id]/page.tsx:41-69`) при чтении
  кода выглядит корректной: при загрузке страницы ищется первая незавершённая
  задача (`findIndex(t => !t.completed)`), если все завершены — вызывается
  `finishQuest`. Поведение на реальном F5 не проверялось живьём (нужен
  браузер) — рекомендую всё же пройти глазами, т.к. корректность зависит и от
  backend-данных, которые не проверялись в этой сессии.

## Не проверено (нужен браузер/живой прогон)

- Реальная раскладка на 360/768/1024/1280px (переполнение контента и т.п.).
- Console-ошибки/warnings React в рантайме.
- Визуальное качество анимаций успеха/shake (конфетти в `.quest-finished`
  имеют `overflow: hidden` и вылет на `translateY(420px)` — контейнер по
  высоте контента, скорее всего, заметно ниже 420px, так что часть падения
  будет обрезана; не фатально, но стоит посмотреть глазами, не выглядит ли
  криво).
- Resume-логика на реальном refresh посреди квеста.
